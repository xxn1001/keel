## 做了什么

- OVMF -> systemd-boot -> UKI A/B -> P0 busybox initrd；raw sparse 64G，GPT 4 分区，
  LVM `system`，erofs `root_a`/`root_b`，ext4 `/etc`，btrfs `var`/`home`，vfat ESP。
- systemd-boot 取自 `out/images/efi-part`；`loader.conf` 只有 `timeout 1`，不拷
  `loader/entries/buildroot.conf`；UKI 为 A+10、B+10、inspector、ESP-fail、recovery。
- `ukify` 不在 host/target，UKI 用 `objcopy`；`keel-boot-ok`/`keel-boot-repair` 是 rootfs overlay 的 spike unit。
- 12 次启动：inspector、bless、B 失败两次、自动回 A + repair、ESP 失败、repair、recovery、final。

## 与设计不符的地方

- §6.2 #6 写"tries 不变"，实测 A+10 -> A+9-1。减一发生在 systemd-boot 启动条目时，
  早于 cmdline。含义：反复进 recovery 会把 A 槽耗成 bad；需要 ESP 上独立的非计数
  recovery UKI 或显式 reset，属于 v0.2。
- A-004 写"A/B/recovery 三个条目"；W-2 只做 A/B。§6.2 #1 也写 recovery UKI 在 v0.2。
- systemd-boot 按 ID 降序排，B 排在 A 前；不能依赖 "keel-a 排在 keel-b 前"。
  `default=keel-a+10` 在 bless 后失效；本次用 `bootctl set-default 'keel-a*'`。
- `systemd-bless-boot` 在 `basic.target` 就标 good，不是 ADR-0015 的 multi-user + 关键挂载检查；关键挂载已在 initrd 完成，但判定点更早。
- `bootctl list` 的 `id` 会去掉 `+N`（`keel-b.efi`），systemd-boot 内部按完整文件名匹配；`set-oneshot` 必须用 source 名。
- W-1 initrd 硬编码 `root_a`，B 槽会静默启动 A；W-2 改为解析 `/proc/cmdline` 的 `root=`，产品 P0 不能硬编码槽位。
- initrd 已挂 ESP 时，gpt-auto-generator 仍生成 `boot.automount` 并失败；cmdline 加 `systemd.gpt_auto=no` 后消失。
- W-0/W-1 内核缺 `CONFIG_EFI`/`EFI_STUB`/`EFIVAR_FS`，systemd-stub 加载 `.linux` 报 "Bad kernel image"；补上后才能启动。
- Buildroot 的 stub 是 `linuxx64.efi.stub`，不是 `systemd-stub*.efi`；objcopy 的 VMA
  必须加 image base（本机 `0x14df90000`），否则 PE 的 RVA 下溢、UEFI 拒载。
