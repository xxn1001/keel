## 做了什么

- 用 raw sparse 64G 做 host loop，建 4 分区、LVM `system`、`root_a`/`root_b`/`etc`。
- 直接对 `/dev/system/root_a` 执行 `mkfs.erofs`，`etc` ext4 播种 rootfs 的 `/etc`，data 建 btrfs `var`/`home` 子卷，ESP 建 vfat。
- 用 busybox + lvm 的 P0 initrd 启动，跑 5 次正常启动和 5 个 `keel.fail=` 注入。

## 命令

```sh
sudo spike/w1/provision-disk.sh
make -C vendor/buildroot BR2_EXTERNAL="$PWD" O="$PWD/out" keel_qemu_x86_64_defconfig

./spike/w1/build-initrd.sh
./spike/w1/run-qemu.py --log out/spike/boot-1.log
```

```sh
mkfs.erofs --all-root /dev/system/root_a out/spike/rootfs
```

## 判定（A-xxx 各自 verified/refuted/untested）

- A-002: untested as written。原假设要求 systemd initrd；本 spike 用 P0 busybox。P0 等价挂载顺序 E2-pass，但不能据此说 A-002 verified。

## 与设计不符的地方

- design §5.2 写 guest 内安装器；W-1 按一次性实验要求改用 host loop。
- design §5.4 的失败项写“进 recovery”；W-1 的 p2 故意留空，所以落到 initrd shell。
- A-002 的原措辞是 systemd initrd；本 spike 用的是 P0 busybox。

## 备注

- `PARTLABEL=` 在无 udev 的 initrd 里不存在；改用 `/dev/vda1..vda4`。
- LVM 用最小 `lvm.conf`（`udev_sync=0`、`udev_rules=0`、`devices.dir=/dev`）+ `vgchange --noudevsync -ay system` + `vgmknodes`。
- `/etc` ext4 必须先播种 rootfs 的 `/etc`；空 LV 会导致 `passwd`、`dbus`、`networkd` 和登录异常。
- VFAT 需要 `CONFIG_NLS_CODEPAGE_437` 和 `CONFIG_NLS_ISO8859_1`。
- Buildroot 默认 BusyBox 没有 `timeout`；用 config fragment 打开。
- `qemu-img` 的 qcow2 不能直接给 `losetup` 当 64G 盘；W-1 用 raw sparse 64G。
